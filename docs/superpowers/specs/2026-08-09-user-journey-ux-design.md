# 用户使用流程体验优化设计

## 目标

在不改变行情数据来源、已保存策略和网格回测计算方式的前提下，让 A 股交易工作台更容易首次上手。

## 优化范围

1. 明确网格策略流程：输入代码、识别标的、生成建议、执行回测、保存策略。
2. 在总览和已选股票详情中增加直接进入网格策略的入口。
3. 将被动或含糊的空状态、连接状态替换为简洁且可执行的下一步提示。
4. 保持现有桌面端固定工作台布局，以及窄屏下的响应式布局。

## 交互设计

### 网格策略

- 用户输入合法六位股票代码并进入网格策略页时，每个代码自动请求一次策略建议。
- 配置面板在可获取时显示已识别的标的名称和当前参考价格。
- 主操作根据状态变化：尚未生成建议时显示“生成策略建议”，有建议后显示“开始回测”，有回测结果后才允许“保存策略”。
- 回测结果面板在尚未回测时说明下一步操作，回测完成后突出关键收益和风险指标。

### 跨页面入口

- 总览页提供简洁的“制定网格策略”入口。
- 已选标的详情在现有“制定计划”旁增加网格策略入口，并携带当前代码进入网格页。

### 状态展示

- 行情加载中或暂不可用时，使用简短说明；需要时提供重试操作。
- 只有实际收到报价数据后，页面才显示行情已实时连接。

## 数据流

- 继续以现有 Vue 状态 `selectedCode`、`gridDraft`、`gridSuggestion`、`gridResult` 为唯一数据来源。
- 保持现有 `/api/grid/preview` 和 `/api/grid/backtest` 接口不变。
- 新增界面辅助逻辑仅从已有状态推导网格策略准备情况，并在请求建议前规范化用户输入的代码。

## 异常处理

- 生成建议失败时不清空表单，继续使用现有提示消息展示 API 返回的错误。
- 仅在用户带着合法代码进入网格页、且该代码尚无建议时自动生成建议，避免重复请求。

## 验证方式

- 检查 JavaScript 语法。
- 运行现有网格策略测试。
- 在本地浏览器中验证桌面端和窄屏下的网格流程、图标渲染，以及页面无横向溢出。
