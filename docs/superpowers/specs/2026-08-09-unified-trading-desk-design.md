# Atlas 统一交易台与量化可信度优化设计

## 目标

在不改变 Atlas 研究工具定位、不接入真实委托能力的前提下，解决桌面端信息层级与滚动体验问题，补足手机端关键导航可用性，并让网格回测结果具备可比较、可诊断、可质疑的量化信息。

本轮同时服务三条核心路径：

1. 选股、加入自选、制定计划、盯盘。
2. 配置网格、运行回测、保存策略。
3. 查看总览和提醒，再进入具体工具。

## 角色审视结论

### UI 视角

- 选股器在 1280×720 视口下存在筛选面板、结果面板和页面内容多层纵向滚动，关键结果被截断。
- 设置项逐行占用独立表面，页面过长且信息分组不明确。
- 手机端六个导航仅显示图标，没有可见文字，识别和切换成本高。
- 当前视觉语言整体成熟，继续沿用深色导航、浅色工作区和珊瑚色主操作，不进行无关换肤。

### 产品经理视角

- 三条路径均为核心，不能把首页降级为单一工具入口。
- 总览需要从信息集合升级为统一指挥台，回答市场怎样、有什么机会、策略是否可靠、当前有哪些风险四个问题。
- 专业工具继续独立存在，总览只展示状态和唯一下一步动作，不复制工具页的完整明细。

### 网站用户视角

- 用户应能在一屏内识别待办和风险，再决定进入选股、策略或执行流程。
- 页面刷新、接口失败或数据不足时，不清空用户输入和最近一次有效结果。
- 手机端优先支持快速查看状态、处理提醒和进入核心工具，不要求复刻桌面端全部密度。

### 量化交易员视角

- 当前回测已经考虑 T+1、100 股整数倍、最低佣金、印花税、过户费、滑点、涨跌停、停牌和训练/验证拆分。
- 现有结果只展示策略收益、回撤、成交次数和期末权益，无法判断收益是否来自标的本身上涨。
- 参数优化只按验证期收益和回撤排序，缺少相对基准、风险调整收益和训练/验证稳定性判断。
- 日线固定路径假设、数据区间和样本外长度需要在结果附近明确披露。

## 方案选择

采用“统一指挥台 + 专业工具页”。

- 未采用“三条独立工作流入口”，因为跨路径切换会多一步，首页无法形成统一风险视图。
- 未采用“可切换工作模式”，因为模式状态会增加学习成本，并可能隐藏跨流程提醒。
- 统一指挥台同时呈现三条路径的状态和下一步动作，各工具页继续保持专业深度。

## 信息架构

### 桌面端

保留六个一级入口，并调整用户可见名称：

1. 今日交易台。
2. 研究选股。
3. 网格策略。
4. 交易计划。
5. 盯盘提醒。
6. 系统设置。

今日交易台包含四类信息：

- 市场状态：指数、候选池涨跌分布、数据更新时间和来源。
- 研究机会：各筛选预设命中数量及进入选股器的主操作。
- 策略验证：运行中策略、待重新回测数量、最近样本外超额收益及进入策略页的主操作。
- 执行风险：止损、目标、计划价提醒和进入提醒队列的主操作。

### 手机端

使用固定底部五项文字导航：总览、选股、网格、执行、更多。

- “执行”页面内用标签切换交易计划和盯盘提醒。
- “更多”包含系统设置和低频账户信息。
- 顶部只保留当前页面标题、数据状态和必要操作，搜索按需展开。
- 宽表可横向滚动；状态摘要和提醒改为纵向列表，不强行压缩为桌面表格。

## 页面交互设计

### 今日交易台

- 第一行展示市场状态、候选数量、运行中策略和待处理提醒。
- 第二行按发现机会、验证策略、执行跟踪排列三个工作区。
- 每个工作区只保留一个主操作，避免多个同权按钮竞争。
- 风险提醒优先于普通活动，止损信号使用明确风险色和数量。

### 研究选股

- 桌面端保留左侧筛选、右侧结果结构，但取消面板内部纵向滚动。
- 页面使用单一纵向滚动；结果表仅在宽度不足时横向滚动。
- 筛选侧栏在足够高的桌面视口中保持可见，不设置独立滚动容器。
- 结果加载、空结果和连接失败分别提供等待、调整条件和重试动作。

### 网格策略

- 配置、生成建议、运行回测、保存策略的状态机保持不变。
- 回测结果新增基准比较、稳健性检查、交易成本和模型边界。
- 数据区间、交易日数量、复权方式、实际来源和数据截止日显示在结果标题附近。
- 样本不足或结果不可靠时允许查看结果，但显示警告并阻止把候选参数标记为推荐。

### 系统设置

- 使用“工作台”“数据获取”“连接状态”三个标签。
- 同类字段放在一个无嵌套卡片的表单区，字段说明紧邻控件。
- 数值输入为单位预留稳定宽度，避免单位换行或与输入内容重叠。
- 保存操作只在存在未保存修改时突出显示。

## 量化指标设计

### 持有基准

使用与策略相同的初始资金，在第一根日线收盘价买入尽可能多的 100 股整数手并扣除买入费用，剩余资金保留为现金，期末按最后收盘价计价。基准和策略均不强制在期末清仓，确保比较口径一致。

新增指标：

- 基准收益率。
- 超额收益率，等于策略收益率减去基准收益率。
- 年化波动率，使用策略日权益收益率的样本标准差乘以 `sqrt(252)`。
- 夏普比率，使用无风险利率 0%，样本不足或波动为 0 时返回空值。
- 总费用，为所有成交费用之和。
- 换手倍数，为成交金额总和除以初始资金。

API 同时返回策略与基准的归一化权益曲线，用于前端对比图。曲线只包含日期和归一化权益，不改变已保存策略结构。

### 稳健性与参数排序

- 参数候选继续使用 70% 训练期和 30% 验证期。
- 候选按验证期超额收益降序、验证期最大回撤升序、训练与验证收益差绝对值升序排序。
- 验证期少于 20 个交易日时标记“样本外过短”。
- 训练与验证收益差超过 10 个百分点时标记“可能过拟合”。
- 无成交、只有单边成交或验证期超额收益不为正时不标记为推荐，但仍保留结果供研究。

## 数据流与组件边界

- `backend/grid_strategy.py` 负责计算策略权益、持有基准、风险指标、成本指标和候选排序，不处理页面文案。
- 网格 API 在现有 `metrics`、`assumptions` 和候选结构上增加字段，保持现有字段兼容。
- `frontend/app.js` 只负责请求、状态推导和格式化，不重复量化公式。
- `frontend/index.html` 负责指挥台、回测报告、标签页和状态组件结构。
- `frontend/styles.css` 负责单一滚动模型、桌面布局和手机底部导航。
- PostgreSQL 继续保存已有策略和最新指标 JSON，不新增真实交易或订单表。

## 状态与异常处理

- 实时行情、缓存行情、历史回测和样本外结果使用不同文案，不用同一个“真实行情”标签混合表达。
- 行情或设置接口失败时保留本地状态，显示失败原因和重试操作。
- 回测数据少于 20 个交易日时不计算年化指标和夏普比率。
- 权益曲线缺失、无成交或基准无法建立时返回可诊断错误，不填充模拟数据。
- 日线回测继续明确披露固定日内路径，不声称可以还原盘口排队、部分成交或市场冲击。

## 非目标

- 不接入券商，不发送真实或模拟委托。
- 不增加新的策略类型、组合优化或机器学习模型。
- 不更换现有行情适配层和数据库方案。
- 不重做品牌配色、图标体系或所有桌面表格的手机专用版本。

## 验证

### 自动测试

- 持有基准费用、股数和期末计价。
- 超额收益、年化波动、夏普、总费用和换手倍数。
- 短样本和零波动返回空风险指标。
- 候选排序优先使用样本外超额收益，并对过拟合和样本过短给出标记。
- 现有 T+1、费用、滑点、涨跌停、停牌、调度和 API 测试全部回归。

### 浏览器验证

- 桌面端使用 1280×720 和 1440×900 逐页检查。
- 手机端使用 390×844 检查底部导航、标题、提醒和宽表。
- 验证页面无内容重叠、无意外横向溢出、关键操作可见、图标正确渲染。
- 验证选股器只有页面纵向滚动，设置标签可操作，回测曲线和空状态均正常显示。
