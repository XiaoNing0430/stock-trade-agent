# 首次使用闭环优化设计

## 目标

让用户在刷新页面或首次进入盯盘中心后，能准确判断策略是否已准备、系统是否正在监控，以及下一步应该做什么。

## 优化范围

1. 页面恢复到网格策略页时，若当前代码合法且尚未有建议，自动生成建议。
2. 盯盘列表为空时，不再显示正在自动扫描或已开启盯盘的误导性状态。
3. 空盯盘页提供明确的“去选股器添加标的”主操作；有标的后才展示自动扫描周期。

## 交互设计

### 网格策略恢复

- 应用初始化完成并加载真实行情后，检查当前视图是否为网格策略。
- 当前代码为六位数字、未处于计算中且没有与该代码对应的建议时，自动调用现有策略建议接口。
- 自动请求失败时保留当前输入和空结果，引导用户手动重试，不自动重复请求。

### 盯盘空状态

- 无监控标的时，状态标签显示“等待添加标的”，统计卡显示“尚未开始”，而不是“盯盘已开启”和“15 秒自动”。
- 空状态操作按钮跳转到选股器，复用现有选股和自选股添加流程。
- 监控标的数量大于零且开关启用时，显示自动扫描周期；开关暂停时显示“已暂停”。

## 数据与边界

- 继续使用现有 `view`、`gridDraft`、`gridSuggestion`、`watchlistCodes`、`monitorEnabled` 状态。
- 不更改行情接口、网格建议接口、数据库结构或盯盘触发规则。
- 自动生成网格建议仅在初始化恢复网格页时执行一次，不覆盖用户已输入的区间或已得到的回测结果。

## 异常处理与验证

- 自动建议的错误继续使用现有消息提示，不影响进入其他视图。
- 使用 Node.js 语法检查和现有 pytest 套件回归验证。
- 在浏览器中验证刷新后网格页自动出现建议，及桌面和窄屏下空盯盘页的文案、按钮和无横向溢出。
